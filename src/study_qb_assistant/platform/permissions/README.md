# 角色与权限

`platform.permissions` 是平台授权的唯一领域入口。

## 模型

- `catalog.py` 定义后端实际支持的权限目录。新增可授权能力时，先在这里声明稳定的权限 ID、分组、名称和说明，再在对应路由执行该权限校验。
- `roles` 表存储系统角色和自定义角色的权限集合。前端通过 `GET /roles` 消费同一份目录，不维护第二份权限清单。
- `superadmin`、`admin`、`user` 在应用启动时由 `PermissionService.ensure_system_roles()` 幂等初始化。旧 `role_permissions` 设置仅用于首次迁移，之后以 `roles` 表为准。

## 安全边界

- 系统角色不能删除，不能修改稳定标识或名称。
- `all` 是公告全量投放的保留标识，不能用作自定义角色 ID。
- 只有 `superadmin` 能创建、删除角色或分配用户角色。
- 系统始终至少保留一名已启用的 `superadmin`，不能删除、禁用或降级最后一名系统所有者。
- 非超级管理员即使拥有 `roles:write`，也只能修改自定义角色，并且新权限必须是其当前有效权限的子集。
- 业务路由优先校验权限而不是角色名称；只有系统所有者操作保留 `superadmin` 身份检查。

## 新增权限流程

1. 在 `catalog.py` 添加 `PermissionDefinition`。
2. 为需要默认获得该能力的系统角色补充权限，并考虑已有运行库的兼容迁移。
3. 在目标 API 路由增加 `require_permissions(...)`。
4. 在前端路由与菜单元数据声明所需权限。
5. 为授权、拒绝和委托越权场景补充测试。
