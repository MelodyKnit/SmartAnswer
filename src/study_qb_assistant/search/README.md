# Search 结构说明

该目录负责本地标准题库检索，当前按“入口 / 匹配策略 / 辅助”拆分：

- `__init__.py`
  - `LocalQuestionIndex`
  - 本地检索入口、结果封装、题库增删改后的索引重建
- `matching.py`
  - 题库匹配专用题干键 `QuestionMatchKey`
  - 精确键索引、题干键索引、n-gram 倒排索引
  - RapidFuzz 精排与安全阈值判断
- `support.py`
  - JSONL 记录读取
  - LLM 自动沉淀题标记判断
  - 元数据数值解析
  - 选项一致性辅助

## 匹配流程

1. 先生成题库匹配专用题干键，去除题型/分值前缀、统一全半角标点、统一填空占位符。
2. 使用 `question_type + title_key + option_signature` 做精确键命中。
3. 精确键失败后，使用 `title_key` 收敛同题干候选。
4. 仍未命中时，使用 2-gram/3-gram 倒排索引召回少量候选，再用 RapidFuzz 计算题干相似度。
5. 精排阶段同时计算选项相似度；选择题必须保持选项顺序高度一致，避免答案标签错位。

## 阈值规则

- 精确键命中返回 `exact_match`，置信度为 `0.99`。
- 强模糊命中要求题干相似度不低于 `0.92`，且第一候选与第二候选综合分差不低于 `0.04`。
- `0.86` 到 `0.92` 的弱模糊区间必须有高一致度选项作为佐证。
- 无选项题只有规范键一致才直接命中；规范键不同的内容级相似不会复用答案。
- LLM 自动沉淀题必须保持选项完全一致，不参与模糊复用。

## 数据库题库与运行时索引

- 题库管理读取数据库题库表，包含 JSONL 同步题、AI 低置信度题和可信 AI 题。
- 运行时本地索引只加载 `active` 与 `trusted` 记录，用于自动作答。
- `low_confidence`、`pending`、`conflict` 记录只用于管理可见和人工复核，不进入自动命中链路。
- `POST /questions/reindex` 会从数据库重建当前进程索引，并继续遵守上述状态过滤规则。

## 设计约束

- 对外统一从 `study_qb_assistant.search` 导入 `LocalQuestionIndex`
- `support.py` 只负责小型辅助函数
- `matching.py` 只负责匹配算法和诊断评分，不直接构造 API 响应
- `__init__.py` 保持检索入口与结果构造，不继续堆算法细节、文件读取和状态判断杂项
