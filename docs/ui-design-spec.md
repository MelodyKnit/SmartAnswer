# StudyQuestionBankAssistant - 界面与提示词设计技术规范

本规范详细阐述了本地学习题库管理与大模型检索增强系统的界面交互、提示词（Prompt）工程、视觉配色系统以及页面布局的设计说明。本系统之所有用户界面、操作提示、表格与日志输出默认且必须使用**简体中文**作为核心语言，以便于国内备考学生及教研人员进行无障碍使用。

---

## 一、 中文界面语言规范 (Interface Language Standards)

为保持系统操作的直观性与一致性，本系统所有交互元素均采用高频、易懂的专业中文术语进行映射。严禁使用生硬的英文直译或未加解释的技术缩写。

### 1. 核心术语中文映射表

| 英文技术术语 | 规范中文表述 | 界面应用场景 | 详细定义与设计考量 |
| :--- | :--- | :--- | :--- |
| **Local Hit / Index Match** | **本地精准匹配** | 题库列表中的解析来源 | 题目与本地已归一化的 verified 题库直接命中，代表无需消耗大模型 Token，答案置信度极高（1.0）。 |
| **LLM Fallback** | **大模型兜底推理** | 查询接口、图表占比与控制台日志 | 本地题库未命中时，系统自动调用配置的第三方或本地运行大模型进行语义理解与推理解答。 |
| **RAG (Retrieval-Augmented)**| **联网检索增强 (RAG)** | 配置面板及流程图 | 大模型回答前，先调取 Web 搜索引擎获取网页最新背景，并将这些网页片段（证据）拼接至 Prompt 输入中。 |
| **Rule-Fix / Known Formula** | **公式修复规则** | 状态标签与解答路径说明 | 针对党政、法律等时政真题中常见的“多对多”、“填空”或具有明确标准答案的题目，通过预置的规则直接匹配修正，免去大模型幻觉。 |
| **Review Required** | **待审核标记** | 状态指示器与管理员纠错队列 | 置信度低于阈值（如 < 0.8）、或是模型兜底返回的答案，系统会自动将其打上“待审核”标签，必须经人工复核。 |
| **Auto-promote** | **自动晋升缓存** | 控制台状态与缓存策略设置 | 当大模型对于同一道未命中的题目返回了多次高置信度且一致的答案时，系统将其升级归档入本地持久化 JSONL 库。 |

## 二、 配色系统设计说明 (Detailed Color Palette System)

界面配色严格遵照 **“深空紫罗兰（Space Violet）”** 的设计理念。通过冷色调暗紫作为底色，亮紫色作为主导视线流，绿色、黄色与粉色分别作为功能性反馈状态色，带给用户一种极具科技感、学术严谨性且高端深邃的视觉冲击。

### 1. 基础调色板与配色规范

```
[深空底色: #090616] -------------------------> 稳重、护眼、专业科研背景
   │
   ├── [卡片背景: RGBA(22, 17, 47, 0.45)] ---> 悬浮毛玻璃层级
   │      └── Backdrop-filter: blur(12px)
   │
   ├── [高光边框: RGBA(147, 51, 234, 0.15)] --> 精细的卡片立体微光
   │
   └── [状态指示色系]
          ├── 主激活色 (紫罗兰): #8b5cf6 ------> 吸引焦点，指示当前活动菜单
          ├── 辅助色 (玫瑰粉): #ec4899 -------> 表示 Fallback 或特殊 AI 处理
          ├── 成功色 (宝石绿): #10b981 -------> 代表高置信度命中、验证通过
          └── 告警色 (琥珀黄): #f59e0b -------> 警示需要人工介入、审核或未配置
```

### 2. 颜色状态矩阵与 CSS 实现细节

本系统中的每种元素在不同交互状态下都有着极其细腻的颜色过渡：

#### A. 紫罗兰主色系 (Accent Violet)
*   **常态 (Normal)：** `#8b5cf6` (RGB: 139, 92, 246)
*   **悬浮 (Hover)：** `#a78bfa` (更亮的浅紫罗兰，提示可交互)
*   **发光阴影 (Glow)：** `rgba(139, 92, 246, 0.35)`
*   **CSS 实现示例：**
    ```css
    .btn-primary {
        background: linear-gradient(135deg, #8b5cf6 0%, #ec4899 100%);
        box-shadow: 0 0 15px rgba(139, 92, 246, 0.3);
        transition: all 0.3s cubic-bezier(0.4, 0, 0.2, 1);
    }
    .btn-primary:hover {
        opacity: 0.95;
        box-shadow: 0 0 25px rgba(139, 92, 246, 0.55);
        transform: translateY(-1px);
    }
    ```

#### B. 成功与命中指示器 (Success Emerald Green)
*   **底色 (Background)：** `rgba(16, 185, 129, 0.15)` (带 15% 透明度的宝石绿，避免亮绿在暗黑背景下刺眼)
*   **文字与边框 (Text & Border)：** `#10b981` (高饱和度绿，突出显示)
*   **视觉寓意：** 用于“本地精准匹配”和“已审核”状态，向用户传递“该数据源安全、经过校验、完全可信”的心理暗示。

#### C. 警告与人工复核指示器 (Warning Amber Yellow)
*   **底色 (Background)：** `rgba(245, 158, 11, 0.15)` (带 15% 透明度的琥珀黄)
*   **文字与边框 (Text & Border)：** `#f59e0b`
*   **视觉寓意：** 用于“待审核”和“模型兜底输出”，提示用户“当前答案仅供参考，大模型可能存在幻觉，建议人工核对”。

#### D. 系统日志控制台 (Console Terminal Black)
*   **背景色：** `#070311` (几乎全黑，与毛玻璃卡片形成深度对比)
*   **前景色：** `#a78bfa` (淡紫色等宽代码字符，降低亮白字符对眼睛的刺激)
*   **时间戳颜色：** `#7c6c9f` (灰紫色暗淡文字，让视线自然忽略辅助时间戳，聚焦于日志内容本身)

## 三、 界面布局设计规范 (Detailed Layout & Spacing)

布局遵循 **非对称式现代控制台结构**，侧边栏作为全局导航控制器，右侧作为自适应多维工作区。

### 1. 布局结构参数表

| 容器名称 | 默认宽度/高度 | 布局技术 (Flex/Grid) | 滚动条行为 (Scrollbar) |
| :--- | :--- | :--- | :--- |
| **侧边菜单栏 (Sidebar)** | 宽: `260px`，高: `100vh` | `Flexbox (column)` | 禁止滚动 (`overflow: hidden`) |
| **主内容工作区 (Main)** | 宽: `calc(100% - 260px)` | `Flexbox (column)` | 允许垂直滚动 (`overflow-y: auto`) |
| **指标卡片行 (Stats Bar)** | 高: `110px` | `Grid (auto-fit)` | 禁止滚动 |
| **主图表/数据表区** | 自适应 | `Flexbox` 或 `Grid` | 禁止外层滚动，表格组件内部 `overflow-x: auto` |
| **底部日志终端** | 高: `400px` | 块级容器 | 允许垂直滚动，自动锚定底部 |

### 2. 边距与间隙 (Spacing System)
系统严格执行 `8px` 倍率步进的间距系统（4px, 8px, 12px, 16px, 24px, 32px, 40px），确保版面具有优美的留白和呼吸感：
*   **外页边距 (Page Margin)：** 主内容区四周统一留白 `40px`，在大屏幕下使视线高度集中。
*   **卡片内边距 (Card Padding)：** 卡片内部统一填充 `24px`，确保文本和图表不紧贴卡片边缘。
*   **网格间隙 (Grid Gap)：** 数据卡片间距 `24px`，输入框与按钮之间的间距 `16px`。

## 四、 大模型提示词（Prompt）设计与工程细节

为确保系统在 Fallback 模式下输出的答案能够被后端解析器安全截取并进行高阶处理，针对大模型（尤其是 Qwen、OpenAI 等）定制了极其精确的提示词规范。

### 1. 单选/多选题决策系统提示词
```markdown
# 角色
你是一个极其严谨的学术题库智能解答器。你的任务是分析输入的题目与选项，依据你内部的通用知识库或给出的检索参考片段，给出最准确的答案。

# 约束条件
1. 必须输出且仅输出一个合规的 JSON 对象，该对象必须包裹在 ```json 和 ``` 代码块中，绝对不能在代码块之外编写任何前言、后记、总结或解释。
2. 选项判断必须完全客观，不要带有猜测性成分。
3. 题目类型规范：
   - 单选题：candidate_answer 必须是单个大写字母（如 "A"）。
   - 多选题：若有多个正确选项，必须以 '#' 符号按照字母顺序拼接（如 "A#C#D"）。
   - 判断题：若题目为判断正误，candidate_answer 只能是 "对" 或 "错"，不要输出选项字母。

# 输出 JSON 格式 Schema
```json
{
  "candidate_answer": "正确选项的字母标号或'对'/'错'",
  "answer_text": "对应正确选项的文本完整内容，如果是判断题，直接重复输出'对'或'错'",
  "confidence": 0.0到1.0之间的置信度浮点数，如匹配程度极其确定则输出 0.99，如模糊不确定则输出较小数值,
  "explanation": "详尽的学术解析，解释为什么该选项是正确的，以及其他干扰项为什么错误"
}
```
```

### 2. 判断题与填空题处理策略
针对**非选择题**，提示词会动态调整。对于“填空题”或“简答题”，Prompt 强制大模型将答案文本填入 `candidate_answer` 和 `answer_text`，并在 `explanation` 中附带背景引文。

### 3. 容错解析机制
为防止大模型偶发性不遵守 JSON 代码块约束（如输出 "这是为您解答的内容：```json ... ```"），后端的 `openai_compatible.py` 解析器已配有以下防线：
1.  **正则提取：** 使用 `re.search(r"```json\s*(.*?)\s*```", raw_response, re.DOTALL)` 剥离任何 JSON 外的多余字符。
2.  **“尽力而为”降级提取：** 若 JSON 依然解析失败，解析器会按行寻找类似于 `"candidate_answer": "A"` 或 `答案：A` 的特征关键字，强制提取出备选字母，防止系统瘫痪。

## 五、 安全合规与隐私红线 (Security & Compliance)

在设计题库控制台时，必须时刻牢记以下合规红线，确保系统仅服务于**本地化、学习辅助、研究参考**场景，严禁演变为外挂或作弊软件：

1.  **敏感密钥强制脱敏：** 
    在控制台界面进行全局状态查询时，返回的 API Key 必须经过脱敏处理。例如，当检测到前端拉取状态时：
    ```python
    # 对 api_key_configured 仅返回 bool 标志，绝不在 HTTP 载荷中传输真实的 STQB_LLM_API_KEY！
    # 运行时日志中的 Authorization 报头必须被正则替换为 "Bearer [redacted]"。
    ```
2.  **本地化数据隔离：**
    所有本地下载的公开评测集原始数据（`data/raw/`）及生成的索引（`data/normalized/`）一律列入 `.gitignore` 保护，绝不上传至 Git 远端仓库，杜绝潜在的知识产权与版权风险。
3.  **禁止自动提交：**
    本题库管理界面的 OCS 适配器仅提供**只读查询**接口（`/ocs/query`），其输出格式符合规范但不提供任何答题表单自动提交、网络评测系统绕过、验证码自动破解或考试平台对抗逻辑。
